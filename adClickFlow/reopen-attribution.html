Ad attribution — forward re-open drops attribution

Fixture for apple-browsers PR #5886. When a link opens a new tab and you tap back to close it, the opener's forward button re-opens that tab. The re-open is created with inheritingAttribution: nil, whereas the original _blank child inherited the opener's ad-click attribution — so the re-opened tab silently loses attribution.

Requirement

This uses the ad-attribution flow, which needs the cross-domain test hosts (www.search-company, www.publisher-company, ad-company) to resolve. Run it against the deployed test site or the browser's UI-test host mapping — not plain localhost, where everything is same-origin and ad-click attribution is never detected.

Steps

  1. Open the search page and tap a "Shopping Tab" ad. These use the /m.js path, so the SERP opens them in a new tab, and they produce active attribution:
    • SERP → tap [Ad 6] (m.js, empty ad_domain)
    • SERP → tap [Ad 8] (m.js, SERP-provided ad_domain)
  2. On the new publisher tab, expand the Resources panel. With attribution active, convert.ad-company…/convert.js and its ping.gif show loaded.
  3. Tap the browser back button: the publisher tab closes and you return to the search page.
  4. Tap the browser forward button to re-open the publisher tab.
  5. Expand Resources again on the re-opened tab and compare.

Expected (fixed): attribution is preserved — convert.js and its ping.gif still show loaded on the re-opened tab.
Buggy (current): attribution is dropped — convert.js shows blocked (and its ping.gif parent blocked) on the re-opened tab, differing from the original.

Tip: also watch the ad-attribution pixels (m_ad_click_active, m_pageloads_with_ad_attribution). If the tab is closed via back and does not return to the search page in a single press, the ad landing added its own history entry — pick an ad whose landing is a single redirect chain (Ad 6 / Ad 8 use 302 redirects).
