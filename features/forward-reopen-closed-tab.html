Forward re-opens a back-closed link tab — opener

Fixture for the iOS change that makes the forward button re-open a link-opened tab that was just closed with back (apple-browsers PR #5886). This page is the opener tab.

The opener remembers the closed child's URL in reopenableClosedTabURL. That value is only cleared on a full-page navigation (didStartProvisionalNavigation), which WKWebView does not fire for same-document navigations (history.pushState / hash changes). So navigating in-page after closing the child leaves the stash set, and forward re-opens the stale child instead of doing nothing.

Steps

  1. Tap Open child in a new tab below.
  2. On the child tab, tap the browser back button. Because the child has no history of its own, back closes it and returns you here.
  3. Back on this page, make a same-document navigation: tap Navigate in-page (hash) or Navigate in-page (pushState). The "Current location" below changes — you have moved on within this tab, with no real page load.
  4. Tap the browser forward button.

Expected (fixed): the in-page navigation cleared the stash, so forward does nothing (the forward button should be disabled).
Buggy (current): forward re-opens the closed child tab even though you navigated in-page after closing it.
