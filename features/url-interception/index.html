Typed-only URL Interception

Some browser features open a native screen when the user enters a specific URL in the address bar. When that should only happen for URLs the user typed or pasted themselves, a web page must not be able to trigger the same screen by navigating to that URL.

This page navigates to a target URL in every way a web page can. For each case, the browser should load the URL as a normal web page (or block it) and should not open the native screen.

The automatic case starts from a fresh page load and waits longer than any browser's user-activation window (5s in Chromium), so the navigation has no user gesture. Don't tap the page while it counts down.

3. Redirects from another page

Each link opens an intermediate page that redirects to url. The server-side case covers a browser that matches the URL after a redirect instead of matching what the user entered.

Redirects from a third-party site use the test domain good.third-party.site, so they only appear when this page is opened on privacy-test-pages.site.
