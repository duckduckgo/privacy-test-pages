Android WebView · stale frame after in-tab navigation

Two near-identical pages, a.html (red) and b.html (green). Each renders instantly and shows a load timestamp that changes every load. Tap the full-width bar at the bottom of each page to navigate A↔B in the same tab (the recycled WebView path).

Expected: after a tap the visible page (colour + label + timestamp) matches the new URL. Bug: on an affected Android WebView reused within one tab, the load finishes (onPageFinished / progress 100) but no frame is committed, so the previous page stays on screen until a re-composite. A screenshot then shows page N-1 while the URL says N. Opening links in a new tab (a fresh WebView per navigation) does not reproduce it.

Stress flags (carried across A↔B links)
Start at A → Start at B →

Resolved start URL: a.html

How to reproduce by hand

  1. Open a start link in the target WebView/browser.
  2. Tap the bottom bar repeatedly to bounce A→B→A… in the same tab.
  3. Watch the colour, the big letter, and the timestamp. If they lag the URL, that is the bug.
  4. The flags above widen the stale-frame window; busy is usually the strongest single trigger.
